# 한 장 · YellowMemo 사용 안내

## 1. 실행과 종료

ZIP을 압축 해제하고 `YellowMemoWidget3.exe`를 실행하세요. 업데이트하기 전에는 기존 앱에서 **⋯ → 앱 종료**를 선택합니다. 컴퓨터를 켤 때 자동으로 시작하는 기능은 없으므로 직접 실행하세요.

**Alt+F4는 완전 종료가 아니라 접기**입니다. 완전히 종료하려면 메뉴 또는 알림 영역 아이콘의 앱 종료를 사용하세요.

## 2. 메모 작성

- ＋ 또는 Ctrl+N으로 새 메모를 만듭니다.
- 제목을 입력하고 노란 본문에 내용을 적습니다. Enter는 다음 줄로 이동합니다.
- 상단 메모 선택 상자에서 다른 메모를 고릅니다.
- 목록 버튼은 검색·정렬이 있는 넓은 창을 엽니다.
- ⋯ → 현재 메모 삭제는 확인 후 해당 메모를 삭제합니다. 삭제 취소 기능은 없습니다.

## 3. 글자와 줄 간격

기본 글자는 10pt, 기본 줄 간격은 22px입니다. 본문에서 글자를 선택한 다음 8~32pt 크기나 굵게 버튼을 적용합니다. 선택이 없으면 앞으로 입력할 글자에 적용됩니다. 빈 메모의 입력 서식도 저장됩니다.

큰 글자를 사용하면 가로선 간격도 넓어집니다. 붙여넣기는 일반 텍스트로 처리하므로 외부 문서의 복잡한 서식은 가져오지 않습니다. 제목은 본문 서식 도구의 적용 대상이 아닙니다.

## 4. 정렬과 검색

| 기능 | 동작 |
|---|---|
| 작성 순 | 최근 생성한 메모부터 표시. 이전 메모를 수정해도 생성 순서 유지 |
| 크기 순 | 본문 글자 수가 많은 순. 같으면 최근 생성한 메모 우선 |
| 검색 | 제목 또는 본문에 검색 문구가 포함된 메모 표시 |

크기에는 공백과 줄바꿈이 포함되고 제목·글자 크기·굵기는 포함되지 않습니다. 내부적으로 UTF-16 문자열 길이를 사용하므로 일부 이모지는 두 글자로 셉니다.

검색은 영어 대소문자를 구분하지 않고 앞뒤 공백을 무시합니다. 검색어를 비우면 전체 목록으로 돌아옵니다. 초성 검색, 오타 보정, 여러 단어의 AND 검색은 없습니다. 검색 결과에도 선택한 정렬이 적용됩니다.

옛 버전에서 생성 시각을 기록하지 않았던 메모는 업데이트 당시의 목록 순서를 한 번 고정합니다. 옛 기록의 실제 생성 순서를 복원하는 기능은 아닙니다.

## 5. 창 사용

위쪽 제목 영역을 끌어 이동하고 가장자리로 크기를 조절합니다. 위쪽 빈 영역을 두 번 누르면 접거나 펼칩니다. ⋯ 메뉴에서 오른쪽 아래 위치로 되돌릴 수 있습니다.

항상 위 기능은 없으며 다른 창 뒤에 둘 수 있습니다. 시계 옆 숨겨진 아이콘에서 메모 아이콘을 두 번 누르면 앞으로 가져옵니다. 마지막 위치와 크기를 기억하며 화면 밖으로 나간 위치는 보정합니다.

## 6. 저장 위치와 오프라인 사용

탐색기 주소창에 다음 경로를 입력하세요.

```text
%LOCALAPPDATA%\YellowMemo\data
```

| 파일 | 역할 |
|---|---|
| widget-notes.json | 현재 메모·서식·선택·창 위치·정렬 설정 |
| widget-notes.json.bak | 직전 저장본 |
| widget-notes.json.lock | 동일 저장 파일을 중복 실행에서 보호 |
| .tmp / .importing | 저장·이전 처리 중 임시 파일 |
| .damaged-날짜 | 손상 파일 복구 시 보존하는 원본 |

약 0.9초 동안 입력이 없고 한글 조합이 끝나면 자동 저장합니다. 아래쪽 저장됨 표시를 확인하세요. Ctrl+S는 즉시 저장·재시도입니다. 정상적인 앱 종료 시에도 마지막 입력을 저장합니다. 강제 종료나 전원 차단 전의 미저장 입력까지 보장하지는 않습니다.

인터넷·로그인·서버 없이 사용할 수 있습니다. 메모는 암호화하지 않은 JSON과 Base64 RTF로 저장됩니다. Base64는 암호화가 아닙니다.

메모가 늘어나면 저장 파일과 메모리 사용량이 늘고, EXE 자체에 메모가 들어가거나 EXE가 커지지는 않습니다.

## 7. 이전 버전에서 업데이트

1. 기존 앱을 완전히 종료합니다.
2. 최초 업데이트 실행은 예전 data 폴더가 실행 파일 옆에 있는 위치에서 합니다.
3. 고정 저장 위치에 메모가 없으면 widget-notes.json 또는 초기 notes.json을 가져옵니다.
4. 고정 저장 위치에 이미 메모나 복구용 백업이 있으면 이를 우선합니다. 옛 파일로 덮어쓰거나 자동 병합하지 않습니다.
5. 예전 data 폴더는 원본으로 남지만, 이후 입력은 AppData에만 저장됩니다.

가져오는 중 원래 앱이 같은 데이터를 사용하고 있으면 잠금 때문에 이전이 중단될 수 있습니다. 기존 앱을 종료하고 다시 실행하세요. 옛 데이터가 손상된 경우 백업 읽기를 시도합니다.

## 8. 앱 이동, PC 이동, 백업

**같은 PC·같은 Windows 계정:** 앱 종료 후 EXE 또는 앱 폴더를 옮겨도 고정 저장 위치의 메모를 사용합니다.

**다른 PC·계정:** 앱을 종료한 뒤 현재 AppData의 data 폴더를 별도로 복사해야 합니다. 새 계정에서 앱을 한 번도 쓰지 않았다면 복사한 data 폴더를 EXE 옆에 두고 처음 실행해 가져올 수 있습니다. 이미 메모가 있는 계정에는 자동 병합하지 않습니다.

정기 백업은 앱 종료 후 AppData의 data 폴더를 별도 위치에 복사하세요. .bak는 직전 저장본 하나이며 장기 이력이 아닙니다. 자동 복구에서도 최근 입력 일부가 없을 수 있습니다.

## 9. 공유하기

배포 ZIP에는 EXE와 이 안내만 있습니다. 다른 사람에게 이 ZIP을 보내면 내 개인 메모가 전달되지 않습니다.

사용하던 data 폴더, AppData 저장 폴더, 옛 메모 백업을 함께 보내면 그 기록도 전달됩니다. 개발 저장소에는 이런 파일을 넣지 마세요. 저장소의 .gitignore는 Git에서 제외할 뿐, 압축이나 일반 파일 업로드를 막아주는 기능은 아닙니다.

## 10. 단축키

| 키 | 기능 |
|---|---|
| Ctrl+N | 새 메모 |
| Ctrl+F | 목록과 검색 |
| Ctrl+S | 즉시 저장 / 재시도 |
| Ctrl+B | 본문 굵게 / 보통 |
| Ctrl+Z | 실행 취소 |
| Alt+F4 | 메모 접기 |

## 11. 알려진 한계

실제 한글 IME에서 모든 받침·입력 속도·PC 조합을 검증하지는 못했습니다. 문제를 제보할 때에는 Windows 버전, 입력기 종류, 재현 순서와 합성 예문을 적어주세요. 개인 메모 파일 전체를 공개 이슈에 첨부할 필요는 없습니다.

현재 배포 파일에는 코드 서명, 설치 프로그램, 자동 업데이트가 없습니다. 오프라인 자동 저장 기능은 PC 간 동기화 기능과 다릅니다.
