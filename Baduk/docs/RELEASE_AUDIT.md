# 공개 전 플레이 이력·민감정보 검토

검토일: **2026-11-01**. 대상은 이 폴더의 소스·문서·스크립트 및 최종 `Baduk-Windows-v1.1.0.zip`입니다. 다른 Hobby 프로젝트와 상위 저장소 전체 이력을 검토했다는 뜻은 아닙니다.

## 1. 저장된 플레이 이력 / 초기 상태

- 배포 실행 폴더와 최종 ZIP에 개인 `.sgf` 기보, Records 폴더, 진행 대국 저장 파일, 플레이 로그, 개인 설정을 포함하지 않습니다.
- 기존 PC의 게임 전용 저장 위치에는 실행 로그와 설정 파일이 있었습니다. 해당 위치에서 `.sgf`는 발견되지 않았습니다. 그 위치의 데이터를 복사하거나 삭제하지 않았습니다.
- 런타임 소스는 시작 시 새로운 `GoGame`을 만들고, 새 대국에서도 새 판을 만듭니다. 저장한 대국을 자동 불러오는 구현은 없습니다.
- 정리한 배포 DLL을 직접 로드하여 9·13·19줄 각각의 초기 돌·착수 기록·패스·따낸 돌 수가 모두 비어 있거나 0임을 확인했습니다.
- 기보는 사용자가 **기보 저장**을 누를 때만 개인 데이터 폴더에 기록됩니다. 이 기능은 배포 후 사용자가 새로 만든 기록을 저장하기 위한 기능입니다.
- 시작 화면의 돌 배치는 코드에 정의된 **미리보기**입니다. 개인 플레이 이력이 아니며, 대국을 시작하면 빈 새 판으로 시작합니다.
- 테스트 코드에는 합법 수 시퀀스가 있습니다. 저장된 사용자 대국이 아니고 `--smoke` 등의 명시적 테스트 옵션에서만 실행합니다. 테스트 출력은 동봉하지 않습니다.

**판단:** 개인 플레이 기록을 동봉하지 않은 배포용 구성입니다. 같은 PC에 남아 있는 별도 사용자 데이터를 삭제하거나 초기화한 것은 아닙니다.

## 2. 개인정보·키·개발 흔적

| 검사 항목 | 확인 및 조치 |
|---|---|
| 실제 API 키·인증 토큰 | 게임은 원격 API 키가 없는 로컬 GTP 방식. 대표적인 키 패턴과 소스의 외부 통신·파일 저장 코드를 검사 |
| 개인키·자격증명 파일 | `.env`, 개인키, 계정 자격 파일 제외. 엔진의 cacert.pem은 공개 CA 인증서 묶음이며 개인키가 아님 |
| 로컬 사용자 경로 | 배포 DLL의 PDB 경로 한 곳을 발견해 파일명만 남기고 제거. 공개 파일 재검사 |
| 사용자명·개인 대화 | 개발 PC 이름·계정 폴더·대화 원문·작업 세션 파일을 공개 자료에 넣지 않음 |
| Git 및 에디터 정보 | 기존 `.git`, 작업 로그, Library·Temp·UserSettings·IDE 캐시, PDB/MDB를 제외 |
| 모델 파일 | 개인 플레이 데이터가 아닌 공식 배포 모델. 다운로드 출처와 SHA-256 기록 |
| 라이선스의 이름·이메일 | 외부 저작자들의 공개 저작권·기여자 고지는 권리 고지를 위해 유지. 이 사용자의 개인정보와 구분 |

초기 단순 바이너리 검색에서는 Windows API 이름 등에 `sk-` 부분 문자열이 있어 토큰처럼 검출됐습니다. 문자열 경계와 실제 값을 검토해 API 이름임을 구분했으며, 모든 NUL 바이트를 제거해 서로 다른 문자열을 이어붙이는 방식은 최종 검사에서 사용하지 않았습니다.

검사 도구를 실행하는 과정에서 생긴 Python 바이트코드 캐시에도 로컬 경로가 포함돼 1차 검사에서 검출됐습니다. 해당 생성 캐시를 공개 준비 폴더에서 제거하고, `.pyc`와 `__pycache__`도 금지·제외 목록에 추가한 후 다시 검사했습니다.

## 3. GitHub 저장소와 Releases 분리

실행 ZIP은 100 MiB를 넘기 때문에 일반 Git에 넣지 않습니다. 소스에는 엔진·모델의 해시와 다운로드 코드만 둡니다. `.gitignore`가 `release-assets/`, 바이너리, 기보, 로그, 설정·캐시를 제외합니다. `.gitignore`만 믿지 않고 실제 전달 파일과 ZIP 내부를 별도로 검사합니다.

## 4. 검토의 한계

이 보고서는 공개 대상 파일에서 확인한 결과입니다. 임의 형태의 모든 비밀값 부재, 외부 라이브러리의 무취약성, 배포자가 이미 올린 과거 Git 이력의 안전성을 보증하지 않습니다. 이후 파일 변경이나 새 Unity 빌드를 하면 다시 검사해야 합니다. GitHub 게시 후 내려받은 첨부물의 SHA-256도 확인하세요.

최종 자동 검사 결과는 `AUDIT_RESULTS.json`, 검증 범위는 `VALIDATION.md`에 있습니다.
